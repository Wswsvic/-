1. 业务概述
   消息通知模块的核心价值是将用户的租约业务动态主动推送给用户，避免用户频繁刷新页面或遗漏重要信息。当用户签约、续约、退租申请、租约到期等关键业务发生时，系统生成一条通知，用户可以点击直接跳转到对应的租约详情页面进行操作或查看。

2. 核心业务流程
   2.1 消息触发场景
   根据项目已有的租约状态流转，确定以下需要触发消息通知的场景：

触发场景	触发时机	目标用户	消息内容模板	跳转目标
签约待确认	管理员在后台创建租约后	租客	您有一份新的租约合同待确认签署，房间：[房间号]，公寓：[公寓名称]	租约详情页（待签约）
签约成功	租客确认签署租约后	租客	租约合同已生效，租期：[开始日期]至[结束日期]，祝您入住愉快！	租约详情页（已签约）
租约已取消	租客/管理员取消租约后	租客	租约合同已取消，房间：[房间号]	租约详情页（已取消）
退租申请待确认	租客提交退租申请后	管理员	用户[用户昵称]提交了退租申请，房间：[房间号]，请及时处理	后台租约管理页
退租申请驳回/通过	管理员处理退租申请后	租客	您的退租申请已被[通过/驳回]，房间：[房间号]	租约详情页（退租状态）
续约申请待确认	租客提交续约申请后	管理员	用户[用户昵称]提交了续约申请，房间：[房间号]，请及时处理	后台租约管理页
续约申请驳回/通过	管理员处理续约申请后	租客	您的续约申请已被[通过/驳回]，房间：[房间号]	租约详情页（续约状态）
租约即将到期	定时任务扫描（如到期前7天、3天、1天）	租客	您的租约即将于[结束日期]到期，请及时办理续约或退租手续	租约详情页

3. 数据库设计
   3.1 通知消息表
   遵循项目规范，所有表均包含create_time、update_time、is_deleted字段（下文省略）。

sql
CREATE TABLE `notification` (
`id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
`user_id` bigint(20) NOT NULL COMMENT '接收用户ID（租客或管理员）',
`user_type` tinyint(4) NOT NULL COMMENT '用户类型：1-租客，2-管理员',
`type` tinyint(4) NOT NULL COMMENT '通知类型：1-签约，2-退租，3-续约，4-租约到期，5-系统公告',
`business_id` bigint(20) NOT NULL COMMENT '业务ID（如租约ID）',
`business_type` tinyint(4) NOT NULL COMMENT '业务类型：1-租约，2-看房预约，3-房间',
`title` varchar(100) NOT NULL COMMENT '通知标题',
`content` varchar(500) NOT NULL COMMENT '通知内容',
`is_read` tinyint(4) NOT NULL DEFAULT '0' COMMENT '是否已读：0-未读，1-已读',
`read_time` datetime DEFAULT NULL COMMENT '阅读时间',
`extra_data` json DEFAULT NULL COMMENT '扩展数据，JSON格式，存储跳转所需的额外参数',
PRIMARY KEY (`id`),
KEY `idx_user_id_type` (`user_id`, `user_type`),
KEY `idx_user_read` (`user_id`, `is_read`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户通知消息表';
字段说明：

user_type：区分通知是发给租客还是管理员，便于后续扩展

business_id + business_type：用于前端跳转，例如business_type=1且business_id=123，则跳转到租约详情页

extra_data：JSON格式，可以存储更丰富的跳转信息，如房间号、公寓名称等，避免前端再查一次接口

is_read + read_time：记录已读状态和阅读时间

3.2 用户最后阅读记录表（可选，用于优化未读计数）
sql
CREATE TABLE `user_notification_read_record` (
`id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
`user_id` bigint(20) NOT NULL COMMENT '用户ID',
`user_type` tinyint(4) NOT NULL COMMENT '用户类型：1-租客，2-管理员',
`last_read_time` datetime NOT NULL COMMENT '最后阅读通知的时间',
PRIMARY KEY (`id`),
UNIQUE KEY `uk_user_id_type` (`user_id`, `user_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户通知阅读记录表';
设计说明：

用于优化未读通知数量的查询性能

查询未读数量时，只需统计create_time > last_read_time的记录数

用户打开通知列表时，异步更新last_read_time

5. 触发通知的实现方式
   5.1 业务埋点
   在租约状态发生变化的地方，调用通知服务发送消息：

示例：租约签约场景

java
// 在租客确认签约成功后
@Transactional
public void signAgreement(Long agreementId) {
// 1. 更新租约状态
leaseAgreementService.updateStatus(agreementId, LeaseStatus.SIGNED);

    // 2. 发送通知给租客
    notificationService.send(
        NotificationSendDTO.builder()
            .userId(leaseAgreement.getUserId())
            .userType(UserType.TENANT)
            .type(NotificationType.SIGN_SUCCESS)
            .businessId(agreementId)
            .businessType(BusinessType.LEASE_AGREEMENT)
            .title("租约签约成功")
            .content(String.format("租约合同已生效，租期：%s至%s", startDate, endDate))
            .extraData(Map.of("roomNumber", roomInfo.getRoomNumber()))
            .build()
    );
}
5.2 定时任务触发
对于租约即将到期、租约已到期等场景，通过定时任务批量生成通知：

java
@Component
public class NotificationScheduledTasks {

    @Autowired
    private NotificationService notificationService;
    
    // 每天凌晨1点执行
    @Scheduled(cron = "0 0 1 * * *")
    public void checkExpiringLeases() {
        // 1. 查询7天内到期的租约
        List<LeaseAgreement> expiringLeases = leaseAgreementService.getExpiringInDays(7);
        
        // 2. 为每个租约生成通知
        for (LeaseAgreement lease : expiringLeases) {
            notificationService.send(
                NotificationSendDTO.builder()
                    .userId(lease.getUserId())
                    .userType(UserType.TENANT)
                    .type(NotificationType.LEASE_EXPIRING)
                    .businessId(lease.getId())
                    .businessType(BusinessType.LEASE_AGREEMENT)
                    .title("租约即将到期提醒")
                    .content(String.format("您的租约将于%s到期，请及时办理续约或退租手续", lease.getLeaseEndDate()))
                    .build()
            );
        }
    }
}
6. 前端交互设计建议
   6.1 通知入口
   在移动端首页或个人中心页面顶部，设计一个小铃铛图标，显示未读数量红点：

text
[🔔 5]  ← 未读数量为5时显示红点
6.2 通知列表页
按时间倒序排列，展示标题、内容、时间

未读消息加粗显示或左侧有蓝色圆点

支持按类型（签约、退租、续约、到期）筛选

点击消息后标记为已读并跳转

6.3 业务页面联动
点击具体通知后，跳转到对应的业务详情页，并自动定位到相关操作区域：

签约通知 → 跳转到租约详情页，自动弹出签约确认弹窗

退租申请结果 → 跳转到租约详情页，高亮显示退租状态

租约到期提醒 → 跳转到租约详情页，显示续约/退租操作入口

7. 总结
   这个设计方案的核心要点：

业务驱动：通知由租约状态变化自动触发，覆盖完整的业务生命周期

精准跳转：通过business_type和business_id实现点击直达业务详情页

双端支持：租客端和管理端都有通知能力，满足不同角色的需求

性能优化：通过last_read_time字段优化未读计数查询

可扩展性：type和business_type采用枚举设计，方便后续扩展其他业务场景

这样的消息通知模块，既能让用户及时了解租约动态，又能引导用户快速处理待办业务，有效提升用户体验和业务处理效率。
