# 尚庭公寓项目问题排查与解决记录 (2026-03-27)

本文档整理了在开发、测试以及部署“尚庭公寓”项目（特别是 `web-app` 和 `web-admin` 模块）时遇到的各项问题及其对应的解决办法。

---

## 1. Knife4j 接口文档显示不全
* **现象**：启动 `AppWebApplication` 后，打开 Knife4j 页面只能看到 `agreement`、`appointment`、`history` 三个控制器的接口，其他的如 `login`、`room` 找不到了。
* **原因**：在 `Knife4jConfiguration` 中使用了 `GroupedOpenApi` 进行了分组，默认只展示了“个人信息”这个分组的内容。
* **解决**：
  1. 在界面的左上角下拉框中切换到“全部接口”或“登录信息”等其他分组即可看到对应接口。
  2. 在 `Knife4jConfiguration` 中增加了一个匹配所有的 `pathsToMatch("/app/**")` 的“全部接口”分组，方便全局查看。

## 2. SpringApplication.run() 缺少 args 参数警告
* **现象**：在 `AppWebApplication.java` 的 `main` 方法中，`SpringApplication.run(AppWebApplication.class)` 被 IDE 标红或警告。
* **原因**：缺少传入方法签名中的 `args` 参数，导致应用无法接收外部传入的命令行参数（例如 `--server.port=9090`）。
* **解决**：修改为 `SpringApplication.run(AppWebApplication.class, args);`。

## 3. 测试登录接口 (/app/testLogin) 报 305 未登录
* **现象**：调用 `testLogin` 获取测试 Token 时被直接拦截，返回 `code: 305, message: 未登录`。
* **原因**：SpringMVC 拦截器 `AuthenticationInterceptor` 拦截了所有的 `/app/**` 路径，只放行了 `/app/login/**`，而 `testLogin` 被算作未放行的业务接口。
* **解决**：在 `WebMvcConfiguration.java` 的 `excludePathPatterns` 中追加配置，将 `"/app/testLogin"` 列入白名单。

## 4. 数据库连接失败（UnknownHostException / Communications link failure）
* **现象**：本地运行报错不知名的主机 `mysql`，或者连接不上云服务器的数据库（连接超时）。
* **原因**：
  1. `application.yml` 中默认的数据库 host 写的是 Docker 的容器内部名 `mysql`，本地环境无法解析。
  2. 哪怕改成了公网 IP，由于云服务器防火墙和安全组没有开放 3306 端口，直接连接仍然会超时或被拒。
* **解决**：
  1. 不开放云服务器公网端口。使用 **SSH 隧道** 的方式：`ssh -N -L 3307:127.0.0.1:3306 root@云服务器IP`。
  2. 将本地的 `application-dev.yml` 的数据库 URL 主机改为 `localhost:3307`，账号密码修正为真实匹配的凭证。

## 5. Knife4j 测试其它接口由于缺失 Token 依然报 305
* **现象**：`/testLogin` 拿到了长字符串 Token，但是再测其它需要通过拦截器的接口依然报 `305`。
* **原因**：HTTP 请求头中没有携带 `access-token` 字段，后端拦截器 `JwtUtil.parseToken` 拿了 null，直接抛出未授权异常。
* **解决**：
  1. 修改 `Knife4jConfiguration`，注入全局的 `SecurityScheme`。
  2. 在 Knife4j 左侧菜单或顶部的**“全局参数设置 / Authorize”**里，将获取到的 `eyJ...` 结尾的 Token 粘贴进名为 `access-token` 的 Header 项里，之后的所有请求都会自动携带。

## 6. Mapper 无法自动装配的 IDE 误报
* **现象**：`LoginServiceImpl` 的 `private UserInfoMapper userInfoMapper` 报红“找不到 Bean”。
* **原因**：虽然 `MybatisPlusConfiguration` 配置了 `@MapperScan` 在运行期代理接口，但是纯接口没有标识注解，IDE 编译器不认识它。
* **解决**：在 `UserInfoMapper` 的接口上添加一个 `@Mapper` 注解，仅仅为了让强迫症患者消除 IDE 波浪线飘红。

## 7. App 登录提示验证码已过期 (505 错误) 与验证码写死
* **现象**：想绕过短信限制直接登录，但是点登录的时候返回 `code 505: 验证码已过期`。
* **原因**：短信接口使用的是阿里云真实服务。如果没有提前调用发送验证码接口，Redis 中就不会有当前手机号的验证码缓存。
* **解决**：
  1. 在 `LoginServiceImpl.sendCode` 里将随机生成的 `code` 写死为 `"123456"`，并注释掉真正的 `smsService.sendSms()` 方法。
  2. **正确的操作顺序：** 前端先填手机号 -> **点击"发送/获取验证码"（此时后端把123456存入Redis）** -> 再手动输入刚才的 `123456` -> 点击登录。

## 8. 本地连接公网 Redis 超时 (Unable to connect to Redis)
* **现象**：虽然在腾讯云放宽了自己家电脑 IP 的限制，但依然无法连接 `150.xxx.xxx.xxx:6379`。
* **原因**：家用宽带 IP 时刻在动态变化，加上 NAT 问题导致实际访问的 IP 和控制台加白名单的可能不同，被安全组直接丢包。直接在公网暴漏 6379 极度危险。
* **解决**：
  和处理 MySQL 一样，用 SSH 隧道方案： `ssh -N -L 6379:127.0.0.1:6379 root@服务器IP`，然后把 `application-dev.yml` 的 Redis `host` 改为 `localhost`。

## 9. 报修记录连表查询出的 roomNumber / apartmentName 出现 null
* **现象**：提交了报修记录，能够在列表查出基本信息，但是“房屋名称”和“公寓名称”是 `null`。
* **原因**：
  1. 驼峰命名没有自动映射导致 `room_number` 到 `roomNumber` 断联。
  2. 前端提交的时候可能根本没带上 `roomId` 导致此列存入 MySQL 时是空的。
* **解决**：
  1. 在 `application.yml` 里面开启 MyBatis-Plus 的 `map-underscore-to-camel-case: true`。
  2. 在 `RepairRecordMapper.xml` 增加 `<result>` 节点显式配置结果映射关系。
  3. 在 `MyRoomController` 补充兜底逻辑：提交维修如果前端不传 `roomId`，就用自己名下**正在履约情况中**的 `LeaseAgreement` 的 `roomId` 自动填充。

## 10. 如何将项目分离多环境并进行部署 (解决云端 502 问题)
* **现象**：打包到云服务器以后，使用 `java -jar` 跑起来，但是一调用接口 Nginx 就返回 `502 Bad Gateway`。
* **原因**：如果不区分环境，云服务器上 `java -jar` 直接运行在宿主机 Linux 上，它不认识 `mysql` / `redis` 这类 Docker 内部通信的域名。从而导致项目一启动连不上 DB 就崩溃退出了。8081 端口自然不会响应该请求。
* **解决**：
  1. 分离配置！建立通用配置 `application.yml`，开发配置 `application-dev.yml`（连 localhost/隧道），生产配置 `application-prod.yml`。
  2. 在 `application-prod.yml` 里，如果宿主机直接跑 Jar，就将 MySQL / Redis 指向宿主机的已暴露端口（比如 `127.0.0.1:3306`），而非 Docker 容器名。
  3. 打包命令：`mvn clean package -DskipTests`。
  4. 启动命令加上指定的 Profile：`nohup java -jar web-app-1.0-SNAPSHOT.jar --spring.profiles.active=prod > app.log 2>&1 &`。
