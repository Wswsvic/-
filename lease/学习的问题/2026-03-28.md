# 2026-03-28 尚庭公寓项目问题及解决记录 (全天汇总版)

## 1. 接口文档展示不全与测试拦截异常
- **Knife4j 文档缺失**：只有部分 controller 的文档出现。
  - **排查与解决**：此类情况需检查 Knife4j 或 Swagger 的 `basePackage` 包扫描范围，确保所有需要暴露的被 `@RestController` 和 `@Api`/`@Tag` 标记。
- **Knife4j 提示"未登录" (Code 305)**：
  - **排查与解决**：项目有 `AuthenticationInterceptor` 拦截器保护，没有或 Token 无效时会抛出异常捕获并返回 `305`。可以测试不拦截的 `testLogin` 或发送验证码接口；要测试拦截接口，需复制 Token 到 Knife4j 全局请求头。

## 2. 区分开发环境与云服务器部署环境的中间件连接问题
- **现象**：上传云服务器后 `app.log` 报 `Connection refused` 导致网关返回 `502 Bad Gateway` 以及 Redis 的 `UnknownHostException` 超时。
- **原因分析**：
  1. 上传后仍然使用了 `dev` （开发环境）配置，尝试连接被映射到了本地的 `3307` 端口或写死的本地回环网络。
  2. 云主机的 `application-prod.yml` 里面 `mysql` 和 `redis` 写成了容器内域名（如 `host: redis`），而宿主机跑的 `.jar` 无法解析该域名。
- **解决方案**：
  - 代码层面：将 `web-app` 和 `web-admin` 的 `application-prod.yml` 内将 MySQL 和 Redis 的 Host 全部改为宿主机的映射 IP `127.0.0.1`，并重新打包（`npm run build` 或 maven package）。
  - 启动命令层面：使用 `nohup java -jar xxx.jar --spring.profiles.active=prod > app.log 2>&1 &` 激活对应环境。

## 3. 移动端“我的房间”模块功能图标点击无响应
- **现象**：H5 页面“我的房间”内“交房租”、“交水费”、“报修”等点击没有反应。
- **原因分析**：阅读 `myRoom.vue` 发现 `navList` 中的配置 `path` 全部为空字符串，且项目中未搭建相关页面。
- **解决方案**：
  1. 新建对应的占位开发页面 `payment.vue` 与 `repair.vue`。
  2. 在 `src/router/otherRoutes.ts` 中注册路由。
  3. 修改 `myRoom.vue` 里循环渲染的图标跳转 `path` 为相应的路径。
  4. H5前端重新编译 `npm run build` 并将打包后的 `dist` 压缩传输至 Nginx 中替换原有网页。

## 4. 彻底解决旧资源图片不显示及 Nginx 代理 MinIO 404 问题
- **初始现象**：前端发起的历史记录图图片请求全解析到了原作者的老 IP 或打不开（图片地址硬编码在 MySQL 数据库内）。且生产环境安全考虑，不应开放大端口。
- **优化与修复过程**：
  1. **代码配置修改**：修改了 `web-admin` -> `application-prod.yml` 修改了相关的 `minio.endpoint`。且理解了 `web-app` 作为纯展示读取者无需配置该信息。
  2. **发现问题**：不直接对外开放 MinIO `9000` 端口时通过 Nginx 代理请求，发现 `curl -I http://localhost/shangting/房间.jpg` 依然报 `404`，Nginx 把位置路由到了本地目录：`/usr/share/nginx/html/shangting/...` 而不是被代理接管过去。
  3. **问题分析**：Nginx 的 `nginx.conf` 设定存在一个默认的 `server` 块监听 `80` 端口。主配置中 `server` 块优先级高于 `conf.d/lease.conf` 等子配置，拦截了所有未显式匹配域名的请求，并没有走 `proxy_pass`。
  4. **解决方案**：
     - 注释掉 `/etc/nginx/nginx.conf` 文件里默认的 `server { listen 80; ... }` 块。
     - 配置业务专用的 `server` 代理块，代理 `/shangting/` 请求至 `proxy_pass http://localhost:9000/shangting/;`。
     - 执行 `nginx -t` 与 `systemctl restart nginx` 验证与重启 Nginx。
  5. **数据库更新**：
     针对硬编码的问题，在数据库批量执行 SQL 更新，将原静态服务器路径或原生 9000 端口去除：
     ```sql
     UPDATE graph_info SET url = REPLACE(url, 'http://139.xxx:9000/shangting/', 'http://150.158.140.21/shangting/');
     UPDATE user_info SET avatar_url = REPLACE(avatar_url, 'http://139.xxx:9000/shangting/', 'http://150.158.140.21/shangting/');
     ```
  6. **最终成果**：只需向外网暴露 80/443 端口，Nginx 安全接管图片的反代回源。由于我们通过 SQL 替换为代理路径，App 端图片正常展现。

## 附录：Nginx 与服务排查常用命令速查
- 测试 Nginx 配置语法：`nginx -t`
- 重启 Nginx：`systemctl restart nginx`
- 监听 Nginx 错误日志 (极有价值)：`tail -f /var/log/nginx/error.log`
- 查看 Nginx 实际加载配置：`nginx -T 2>&1 | grep "listen 80"`
- 查看 MinIO 容器内部文件状态：`docker exec -it minio ls /data/shangting/`
